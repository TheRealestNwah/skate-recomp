# Vector bounds comparisons

## Reproduced defects

The pinned SDK emits ordered greater-than and less-than comparisons for `vcmpbfp` and `vcmpbfp128`. A NaN in either source therefore produces a zero lane mask. The expected result is `0xC0000000`, setting both bounds bits. The record form also uses the general vector comparison CR6 helper, which sets LT when all lanes are outside their bounds. Bounds comparisons should set only EQ when all lanes are in bounds and clear the other CR6 bits. [SDK vector builder](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/src/codegen/builders/vector.cpp) · [Xenia Canary correction](https://github.com/xenia-canary/xenia-canary/commit/a1ad74c)

An offline executable compiled the current Generated body for `vcmpbfp. v0,v0,v13` against the pinned SDK headers. All four left lanes were quiet NaN and all bounds were 1.0. The result was `00000000` per lane with CR6 `2`, rather than `C0000000` with CR6 `0`. With all left lanes 2.0 and bounds 1.0, the lane mask was correctly `80000000`, but CR6 was `8` rather than `0`. These are separate defects. [NaN issue #105](https://github.com/TheRealestNwah/skate-recomp/issues/105) · [CR6 issue #106](https://github.com/TheRealestNwah/skate-recomp/issues/106)

The first Host probe also reproduced a dependency problem in the bundled SIMDe header. Its `simde_mm_cmpnle_ps` and `simde_mm_cmpnge_ps` definitions delegate to ordered comparisons and exclude NaN. With left 0 and a quiet NaN bound, a hook using those helpers returned zero. The Host fix instead explicitly ORs the unordered mask into both ordered comparisons. The bundled header remains unchanged. [Dependency issue #107](https://github.com/TheRealestNwah/skate-recomp/issues/107) · [Host implementation](../../src/skate_app.cpp)

## Host correction and offline checks

The Host snapshots both vector inputs, constructs the upper and lower bounds bits with an explicit unordered mask, and writes only EQ or zero for record forms. Wrappers handle destination/source aliases without listing a register twice in hook metadata. This avoids the existing SDK hook parameter defect. Stock ReXGlue SDK 0.10.1 remains pinned. [Host implementation](../../src/skate_app.cpp) · [Hook parameter issue #97](https://github.com/TheRealestNwah/skate-recomp/issues/97)

The original USA XEX instruction words and decoded operands matched all 45 Generated sites, including 18 record forms. The metadata hooks replace one instruction at each site. There are 16 sites with distinct registers, 19 that overwrite the left operand, and 10 that overwrite the bounds operand. No site uses the same register for both inputs. [Hook metadata](../../config/skate-vector-bounds.toml) · [USA XEX identification](02-dump-inspection.md)

The corrected Host functions passed 12,016,640 offline hook cases against a separate scalar reference. The probe covered all five wrappers, both destination/source aliases, source preservation, all four rounding modes, and both initial denormal modes. Inputs included positive and negative zeros, subnormals, boundary equality, negative bounds, infinities, quiet and signaling NaNs, every combination of in-bounds and out-of-bounds lanes, and 300,000 random vector pairs per mode. Record forms cleared every CR6 bit except the expected EQ result. The checks also confirmed vector flush mode and preservation of the rounding mode. Probe sources, executables, and results remain under ignored `build/m4-technical/`. [Host implementation](../../src/skate_app.cpp) · [Pinned register types](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/include/rex/ppc/context.h)

The full local Port build completed successfully. An emission check found all 45 hook calls followed by jumps to the next instruction, 384 unique configured instruction hooks in total, and all 115,508 dispatch registrations retained. Markdown lint passed for the changed guidance and notes. These checks compile the Port and inspect its Generated output without executing the game. [Build entry point](../../scripts/build-port.ps1) · [Hook includes](../../config/skate.toml)

No game was launched for this audit. **[Inference]** Incorrect masks or condition flags could change Guest branches that consume bounds checks; this audit does not establish a particular visible symptom. Camera and surface visibility checks are included in the maintainer's [controller test plan](05-m4-baseline.md). Gameplay results and the Career log remain unfilled by this work.

## Adjacent integer instruction checks

A separate offline probe passed 5,345,792 cases covering signed byte, halfword, and word average helpers, unsigned word saturating addition, byte permutation, and the emitted rotate/insert expression. It exhaustively checked all signed-byte input pairs, every permutation control byte with its upper bits ignored, and all 64 rotate/insert control combinations with distinct and aliased source/destination vectors. It also checked one million random vector pairs for the arithmetic and permutation helpers. Expected values came from wider scalar arithmetic and explicit Guest element indexing. These checks required no Host or SDK correction. [Pinned helpers](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/include/rex/ppc/intrinsics.h) · [Pinned vector emitter](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/src/codegen/builders/vector.cpp) · [Xenia instruction semantics](https://github.com/xenia-project/xenia/blob/master/src/xenia/cpu/ppc/ppc_emit_altivec.cc)

The Port contains 201 `vaddsws` and 159 `vsubsws` sites. A second probe compiled the actual Generated instruction bodies for all six source/destination alias forms present across those sites, with register numbers normalized for the probe. All 6,000,294 cases passed against signed 64-bit scalar addition/subtraction clamped to the signed 32-bit range. This included all 49 pairs of seven boundary values and one million random vector pairs per form. The result covers emitted saturation and alias behavior. It does not execute the surrounding Guest routines or establish gameplay outcomes. The probe and its compiler output remain in ignored `build/m4-technical/`.
