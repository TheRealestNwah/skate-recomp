# XMA and Windows audio output

## Audio path in ReXGlue 0.10.1

The USA XEX imports 16 XMA context functions for allocation, initialization, enable and disable, and input and output buffer management. ReXGlue implements the context functions through its XMA decoder. An enable command can decode inline and wake the `XMA Decoder` worker. The context mutex serializes decode, disable, and release. Release clears the Guest context and resets the decoder state. The pinned SDK has no equivalents for the Canary `use_dedicated_xma_thread` and `xma_decoder` options. [XEX imports](02-dump-inspection.md) · [SDK XMA imports](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/src/kernel/xboxkrnl/xboxkrnl_audio_xma.cpp) · [SDK decoder](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/src/audio/xma_decoder.cpp) · [SDK context](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/src/audio/xma_context.cpp)

The Guest registers its mix callback at `XAudioRegisterRenderDriverClient`. A separate SDK `Audio Worker` calls that function and the Guest submits six planar big-endian float channels through `XAudioSubmitRenderDriverFrame`. The SDL driver copies each 256-sample-per-channel buffer before queuing it and folds the channels to stereo if the device opens with one or two channels. `XAudioQueryDriverPerformance` is a stub. The SDK returns a fixed speaker configuration, unchanged category volume, and a zero mask for category volume changes. [Host import audit](../../src/kernel_audit.cpp) · [SDK XAudio exports](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/src/kernel/xboxkrnl/xboxkrnl_audio.cpp) · [SDK worker](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/src/audio/audio_system.cpp) · [SDK SDL driver](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/src/audio/sdl/sdl_audio_driver.cpp)

## Unattended Windows playback check

The November 15, 2026 test used the USA disc, stock ReXGlue runtime DLL, the scripted Free Skate controller, default 60 Hz Guest timing, and RTV with draw extent estimation. The controller loaded a copied test skater, selected the Community Center spawn, and sent eight pushes in Free Skate. A Windows process loopback capture recorded only Port output at 48 kHz stereo. A test-only Host probe counted render submissions and applied the SDK's stereo fold to copies of Guest buffers to measure their peak. The default save directory and normal Port executable were kept outside the instrumented runs. [Scripted controller](04-renderer-performance.md) · [Windows process loopback](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/)

- With the default WASAPI path, the named headphones negotiated two channels. Three captures showed startup movie audio followed by output near the capture noise floor in the menu and Free Skate. The in-game music, sound effects and dialogue sliders were up. Free Skate windows measured about −92 to −96 dBFS RMS. The probe still saw about 187–188 Guest buffers per second and nonzero stereo-folded peaks. [Intermittent Windows output investigation #60](https://github.com/TheRealestNwah/skate-recomp/issues/60)
- Changing the SDK stereo LFE weight from 0 to 0.316 and back in the same process did not restore the output. The calculated fold already contained signal from other channels with the default weights.
- Forcing `SDL_AUDIO_DRIVER=directsound` negotiated six channels on the same named endpoint. Windows loopback recorded menu and Free Skate signal. The three five-second windows spanning the push sequence and coast measured −46.9, −43.4 and −46.0 dBFS RMS. A second launch through `run-port.ps1 -DirectSound` negotiated six channels again and produced captured Free Skate audio.
- A later WASAPI run on the same endpoint captured normal game signal during Free Skate before any test signal was enabled. A temporary 750 Hz tone at 0.035 full scale in both front channels yielded a loopback peak of about 0.0205 full scale, consistent with the SDK's default stereo scale of about 0.586. Returning to the original buffers restored game signal.

The maintainer reported having to reapply Windows Volume Mixer mute on each launch. The earlier captures did not record the mixer's per-process state, so those low captures cannot establish a WASAPI defect. **[Inference]** The later run shows that the stock stereo path can carry the expected signal. Reproducing the earlier loss requires holding the process volume and mute state constant.

The normal Port executable also crashed at Guest address `0x0000003C` when a test forced the unavailable SDL `disk` backend. The SDK logged an audio initialization error immediately before the crash. This test establishes a failure to handle backend initialization errors. It did not disconnect or disable the user's endpoint. [Audio startup issue #59](https://github.com/TheRealestNwah/skate-recomp/issues/59)

## Flickit input

With the default 60 Hz Guest mode, the test-only controller received about 60 state reads per second in Free Skate at Community Center. It sent full right-stick down, full up and then neutral. The Guest showed an airborne skater and scored a switch ollie. This single sequence checks button and axis delivery at the sampled cadence. It leaves the original console's input cadence, short flicks and a wider trick set to verify. [SDK input export](https://github.com/rexglue/rexglue-sdk/blob/v0.10.1/src/kernel/xam/xam_input.cpp) · [Controller baseline](05-m4-baseline.md)

## Streaming smoke test

In one muted run, the controller skated at Community Center, quit Free Skate to the main menu, loaded the Library in Downtown, and skated there. The test-only Host counted 1,857 `NtReadFile` calls requesting about 202 MiB in the first load window and 1,833 calls requesting about 192 MiB in the second. XMA enable calls and audio submissions continued with device output muted. The log recorded no APU warning or error, and the skater responded after each load.

The probe saw physical-memory frees during boot and none through the two load windows. These observations cover two locations and one return to the main menu. A Guest allocator and decoder trace is still needed to check buffer lifetimes during longer play.
